# 植物気候マップ

Plant Climate Map — 植物のふるさとと、育てる場所の気候を比べる。

本書は、このツールの狙い・UI・データ解釈・検査／公開契約の唯一の説明正本です。個別植物の事実・評価と段階定義は `data/plants.json`、帰属・利用条件は [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) が所有します。ルート案内と移行用引き継ぎは入口・時点説明であり、別の現行仕様を管理しません。

公開名は「植物気候マップ」、公開repoは `nature-wx-lab/plant-climate-map` です。ローカルcloneのフォルダ名と内部の配信識別子には旧名 `plant-climate-mesh` が残っています。旧Pages URLは公表前に移行したため、旧URLへの転送・案内を前提にしません。

世界地図をクリックし、日本では気温・降水・日射・相対湿度の約1km独自推定値、それ以外ではNASA POWERの1991–2020年気候平均を表示する公開試作ツールです。

地図上部の「平面／地球儀」で投影を切り替えます。植物・気象要素・年/月・表示設定・A/B・比較/季節合わせ・パネルの状態を維持し、気候数値を再計算しません。地球儀は正射図法で、ドラッグで回転し、2本指で拡大縮小できます。裏側の地点は非表示にし、A/Bへ移動ボタンで中央へ戻せます。

地球儀も日本約1kmの同じ数値タイルを使い、拡大時に表示範囲の格子を描画します。全球PNGは元の最近傍色を球面へ写します。緯度±85.05°より極側には元データがなく、色や地点値を補いません。WebGL非対応・接続喪失時はCanvas描画へ切り替えます。

- 公開URL: `https://nature-wx-lab.github.io/plant-climate-map/`
- 表示要素: 地上2m気温、補正済み降水量、全天日射量、地上2m相対湿度
- 分布図: 日本の気温・降水・日射・湿度は約1kmの推定値を広域では概要画像、拡大時には元格子から描画。日本以外は従来のNASA POWER表示
- 表示値: 年平均、日最高・日最低気温、全天日射量、日平均相対湿度の日別気候平均、月別グラフ、平均日最高・平均日最低を含む月別数値表
- 比較: 選択地点を1か所だけ基準に固定し、次に選んだ地点のグラフへ重ね表示。年平均値と月別表には基準との差を表示し、表示の一時OFFと基準解除にも対応
- 植物案内: 原種等と園芸品種群を区別して検索。個別値はカタログ、集計は下のカタログ節を参照。Kewの原産地域をつないだ外周を黒太線で示し、選択では画角を維持。全件に原産地の参考度★1〜5・理由・出典を表示し、原産地域を特定しない園芸品種群等には囲いを作らない
- 画面: 植物一覧を連続操作しながら地図を確認し、地点の概要では4要素の年間変化を一度に読む。細かい解説・表示設定は必要なときに開く。操作上の決定は下のUI節を正とする
- 地図: Webメルカトル図法／正射図法（地球儀）、Natural Earth 1:50m境界。日本の有効メッシュでは標準3次メッシュを選択し、日本以外はNASA格子を選択。国・地域と周辺都市の目安を表示
- 気候区分: Beckほか（2023）のケッペン＝ガイガー気候区分1991–2020年・0.1°版を、ボタンで重ね合わせ表示
- 地図操作: ホイールで拡大縮小、左ドラッグで移動。地点クリックでは現在の縮尺を維持。東西方向は境界なく連続移動
- 気温グラフ: 縦軸は5℃刻みで、0℃と30℃を強調。0〜35℃は常時表示し、データが範囲外の場合は5℃単位で拡張
- 降水量: 日本では日別1km推定値を月・年に合算。その他はAPIの月別日平均量を各月・年の平均日数で月・年降水量へ換算

## 狙いと判断の立て方

苗ラベルや一般的な育て方の「原産地○○」「耐寒温度○℃」「蒸れに注意」を、原産地域の季節変化と自分の栽培環境へつなげるためのツールです。気温だけでなく雨・日射・湿度を合わせて読み、保温、低温確保、雨よけ、通風、遮光などを考える材料にします。自生地をそのまま再現すればよいという処方や、栽培可否の判定は提供しません。

使い方は植物選択からの探索と、登録植物を選ばない任意地点の探索の二つです。NatureWxLabのnote・YouTube・公式HPで植物と気候を解説する際の共通基盤として育てる構想です。現行の案内は原種等の気候を調べる出発点であり、園芸品種別の耐性データベースではありません。左欄の大見出し「植物から探す」と説明文「原産地を知る → 地図で気候を比べる」は削除済みで、再び一覧の上へ積みません。

## 使い方とUIの決定

1. 植物名・学名・別名、またはジャンルで探し、植物を選ぶ。黒太線は比較候補となる原産地域の概略。線の中の任意地点を選ぶ前に、解説で対象の種・産地・標高・生育場所を確かめる。
2. 地図で気温・降水量・湿度・日射量と年・月を切り替える。濃さ・表示有無・気候区分は「表示設定」で操作する。
3. まず栽培地点などの地点Aをクリックし、「Aを基準に固定」を押す。「地図で地点Bを選ぶ」から原産地域等の比較地点をクリックする。原産地をAにして逆向きに比較してもよい。A/Bの入れ替え、重ね表示の一時OFF、基準解除ができる。
4. 「概要」で年値・季節の特徴・4要素の月別グラフを読み、必要なら気温・降水・日射・湿度・月別のタブを開く。月や線に触れて値を読む。
5. 南北半球の比較では「季節を合わせる」でBをAの暦へ移動する。表示中の移動量とBの元の日付を確認する。雨季や生育期が厳密に一致する操作ではない。
6. 地図が隠れるときは結果パネルのヘッダーを左右・下へ動かす。残ったヘッダーを掴んで戻せる。四隅は等比拡縮、閉じたパネルは地図右下のボタンから同じ状態で再表示できる。

### 地図と連続的な植物選択

- 初期画角は、アジア・太平洋を中央に世界の一周がぎりぎり入る見渡しを優先する。初期中心は東経146°・北緯34°、初期倍率は表示枠の縦横比に応じて1〜1.5625とする。極域はWebメルカトルの表示限界まで。「全体」は倍率1の全体表示に戻す。
- 植物選択で自動ズーム・自動中央移動をしない。「原産地へ移動」の明示操作だけが倍率を維持して中心を動かす。現行の移動・投影切替は `app.js` の `focusPlantOrigin` / `setProjection` を参照する。
- 植物を連続的に切り替えて地図を比べられるよう、選択後も一覧・一覧のスクロール位置・キーボードフォーカスを維持する。スマートフォンの一覧も手動で開閉し、選択では閉じない。
- 左側は検索・ジャンル・植物一覧を主とする。参考度の理由、原種と園芸品種の注釈、出典は「解説・出典」から開く。気象要素と年・月は地図上部の横一列で切り替え、凡例は地図内に置く。主要操作に大きなカードや説明枠を重ねて地図・一覧の面積を奪わない。
- ヘッダーと操作列は薄くし、地名・赤道のために常時表示の二段目を増やさない。各植物の星と選択カードの星の上には、小さい「原産地の参考度」を表示する。スマホでは「植物を選ぶ」ボタンで一覧を開閉する。
- UI改修では既存の機能を維持する。公開画面の説明は読者の判断に必要な出典・限界に絞り、内部保存先や作業工程名を表示しない。公式HP・YouTube・note・Xへの導線を置き、使い方noteは実際に作成されるまで架空のリンクを置かない。

### 投影・地名・背景表示

- 平面／地球儀で植物選択、気象4要素、年・月、濃さ、原産地域、国名・首都・広域区分、赤道、A/B比較・季節合わせを共通利用する。投影の違いから気候値を作り替えない。
- 国名・首都・広域区分をそれぞれON/OFFにする。広域区分はNatural Earthの分類を基に、地域色の境界と名前で範囲を示す。ズームで国名を地域名に置き換えない。中心の国・対応地域・首都が近接する場合は位置を調整して共存させる一方、密集地の間引きは維持する。全ラベルの重ね表示や、遠くの空き場所への引出線配置は採用しない。
- 赤道も独立ON/OFF。細い淡赤色の線で示す。現在の描画は `.equator-line`（色 `#c95f69`、不透明度0.7、幅1）と `.equator-halo` を使用する。
- 表示設定では標準／詳細地図／航空写真・衛星画像を切り替え、地図の濃さを0〜100%で調整する。地形は別に重ね、白黒の陰影を初期設定とし、カラー（標高と陰影）にも切り替えられる。地形と気象レイヤーの濃さも独立する。
- 詳細な地図・航空写真は主に日本を対象とする。海外は広域画像のため拡大しても細部が増えるとは限らない。GSIタイルは表示中の範囲だけ取得し、欠測を勝手な画像で補わない。出典・通信・利用条件は帰属正本を参照する。
- 地球儀の背景は暗い宇宙。`globe.js` の固定シードによる星と星座の模様を、地球儀と同じ向きの変化に連動させる。ズームしても星空自体を拡大せず、操作が止まれば背景も静止する。背面の星や星座線を可視側へつなぎ直さず、平面では背景を隠す。星座は背景用の描画で、実際の星表・日時に対応する天体配置ではない。地球の気候面へ背景色を混ぜない。

### 概要と浮動パネル

概要は、大きな数字カード4枚だけで終わらせず、この1ページで地点の年間気候を把握する入口にする。年平均等は小さくまとめ、月平均気温と平均日最高・最低、月降水量、日射量、湿度を**共通の月軸を持つ4段のグラフ**で同時表示する。単位の違う要素を無理に一つの縦軸へ混ぜない。月別値に基づく特徴、各要素の最少・最多月、4要素をまとめた月の読取り、A/Bの重ね表示を備える。重ね表示OFFでも現在値がBであることを明示する。

概要の特徴文は、月平均気温・月降水量の範囲を便宜的な閾値で説明したもので、ケッペン区分の自動判定や栽培診断ではない。例えば月平均20℃以上、気温の年較差5℃以下、各月20mm以下、毎月100mm以上等の条件を使う。湿度・日射は各段と月の読取りで示し、降水量から用土や葉が乾く速さを推定しない。

PCの概要は年値カードを左の縦一列、4段グラフを右へ配置し、注釈・取得状態・月の読取り・出典への入口は下段の細い一行へ集める。地点情報、見出し、タブの高さも抑える。グラフの縦幅を優先し、スマホでは幅に合わせて再配置する。

結果パネルはPCで初期4:3、スマホ等では利用可能な高さに合わせる。ヘッダーで移動、四隅で0.65〜1.45倍へ等比拡縮する。左右・下側には大部分を画面外へ逃がせるが、戻すためにヘッダーを残す。左右は原則140px以上、比較中は右端の操作ボタン幅に加え64pxの掴める部分を確保し、表示枠が狭い場合はその幅に収める。下側はヘッダー全高を残し、上端は表示中の地図内に留める。境界判定には地図と画面の重なる範囲を用い、画面サイズ変更後も掴める位置へ制限する。ヘッダーのボタン押下をドラッグと取り違えず、パネル移動で地図を移動させない。

## データ契約

### 全球分布図

全球の背景分布図はNASA POWER Data v10の公開AWS Zarr月別データから事前生成した静的PNGです。日本は全要素で約1kmの独自推定値を上書きします。ブラウザからAWSへ接続せず、選択された要素・期間の画像だけを同一GitHub Pages配信元から読み込みます。

- 気温・降水量・相対湿度: `power_merra2_monthly_temporal_lst.zarr`、元格子0.5°緯度×0.625°経度
- 日射量の1991〜2000年: `power_srb_monthly_temporal_lst.zarr`、元格子1°×1°
- 日射量の2001〜2020年: `power_syn1deg_monthly_temporal_lst.zarr`、元格子1°×1°
- 期間: 1991年1月〜2020年12月、Local Solar Time
- 月表示: 同じ月を30年分平均。降水量は月の日数を掛けた月降水量
- 年表示: 気温・湿度・日射量は月の日数で加重した年平均、降水量は12か月の月降水量の合計
- 投影: 元格子の最近傍値を2048×2048ピクセルのWebメルカトル画像へ変換。格子間の平滑化は行わない

日本の気温・降水・日射・湿度は、約1km格子の月別・年別数値を別に配信して重ねています。ズーム32未満は2048pxの概要画像、それ以上は表示範囲に必要な1km格子の数値を読み込み、画面解像度で再描画します。広域画像は視覚的なプレビューで、地点値は画像の色から逆算せず日別格子値を読み込みます。日本の欠測部分もNASAの色で埋めません。

### 日本の約1kmメッシュ

対象は日本の標準3次メッシュ387,717格子。気象庁の1991–2020年の日別平年値と既存の月別約1kmメッシュを組み合わせて推定した、年内366日分の気温（平均・最高・最低）・降水量・全天日射量を使用します。相対湿度は1991–2020年の観測所の日平均値と公式の月別平年値を基に日別約1kmメッシュを独自推定し、383,735格子をサポートします。いずれも気象庁が公表する公式な「1km日別平年値」ではなく、日別の実測値を格子ごとに復元したものでもありません。推定できない格子は欠測として扱い、NASA値で埋めません。

公開用の派生数値は4桁のメッシュ接頭辞単位に圧縮し、クリック時は当該区画の6要素だけ取得します。公開先には観測所情報や作成時のローカル情報を含めません。地図用の月値は通常年の365日で集計し、2月29日を除きます。降水量の分布図だけは着色のため整数mmに丸め、地点の月・年表示は日別の0.1mm値を合算します。相対湿度の月・年値は日別値の平均です。日射の推定に使える観測所が少ない地域、地形・沿岸・都市の細かな差には不確実性があります。最低気温は既存の月別1km最低気温メッシュに合わせて再計算し、最低値が同じ格子・暦日の平均値を上回らないことを公開前に全件検査します。これは気象庁の公式1km日別値や局地的な実測精度を保証するものではありません。

### 地点詳細

日本以外では地点選択時だけNASA POWER Climatology API・Daily APIへ問い合わせます。日本のメッシュ選択ではNASAへ接続しません。

```text
https://power.larc.nasa.gov/api/temporal/climatology/point
parameters=T2M,PRECTOTCORR,ALLSKY_SFC_SW_DWN,RH2M
community=AG
start=1991
end=2020
format=JSON
```

同時にDaily APIから1991年1月1日〜2020年12月31日の`T2M_MAX`、`T2M_MIN`、`ALLSKY_SFC_SW_DWN`、`RH2M`を取得し、日最高気温、日最低気温、1日合計全天日射量、日平均相対湿度を各暦日について平均します。通常日は30年分、2月29日は8年分です。月別数値表では、各月に含まれる有効な日最高・日最低気温をそれぞれ平均します。API応答が欠けた日は集計から除き、日別データだけ取得できない場合も月別・年平均値は表示します。

日本以外の橙枠は、クリック位置に最も近いMERRA-2格子中心へそろえた約0.5°緯度×0.625°経度の気象格子です。気温・補正済み降水量・相対湿度はその元格子の空間平均として扱います。日射量は同じ中心座標に対応する別の1°×1°格子です。日本の選択枠は全要素で約1kmの標準3次メッシュです。

独自算出値を気象庁の公式な「平年値」と呼ばず、画面では「1991–2020年の気候平均」と表示します。降水量はAPIの月別・年平均日量に、1991〜2020年の各月または1年の平均日数を掛けて月降水量・年降水量へ換算します。この30年間には閏年が8回あるため、2月は28＋8/30日、1年は365＋8/30日として計算します。

国・地域はNatural Earth 1:50m Admin 0 Countriesのポリゴンに気象格子中心が含まれるかをブラウザ内で判定します。周辺表示はNatural Earth 1:10m Populated Places Simple v5.1.2から、`SCALERANK <= 5`、国首都、地域首府に該当する2,906地点を抽出し、同じ国・地域内で最も近い地点との方角・概算距離を球面距離で求めます。45km以内は「周辺」と簡略表示します。これは位置の目安であり、行政区画を判定するものではありません。海上、境界付近、収録地点がない地域では座標または国首都を代替表示します。

比較基準は1地点だけです。「基準に」で現在地点と取得済みデータをブラウザのメモリ内に保持し、次の地点を選ぶと比較先を実線、基準気温を黒縁の実線で重ねます。基準地点はページ再読み込みで消去され、端末の永続ストレージには保存しません。

地点カードと各グラフの凡例ではA（基準）・B（比較先）の国・地域と周辺都市の目安を明示します。気温の最高は暖色、最低は寒色とし、両地点とも実線のまま基準Aだけを黒縁で識別します。日別グラフは全期間・3か月・1か月の切替、拡大縮小ボタン、ホイール・2本指による拡大、拡大後のドラッグによる期間移動、線に触れたときの日別値の読取りに対応します。約1kmメッシュは値の推定対象範囲であり、観測所の日別実測や局地的な栽培環境を保証する解像度ではありません。

南北半球の地点を比べるときは「季節を合わせる」でBの日別曲線を183日、月別降水量と月別表のB値を6か月巡回させ、Aの暦を横軸にして重ねられます。日別の183日は366日暦の半周であり、Bの実際の暦日はグラフの読取りに表示します。月別表はAの月と対応するBの月を併記します。年平均・元データ・地図の分布は変えません。切替はブラウザ内だけの表示状態で、基準を解除または新しい基準にしたときはOFFへ戻ります。

### 気候区分

### 今後のカタログ拡充の基準

一般に購入できる植物・品種を、ホームセンター、園芸店、専門店、アクアリウム店、植木販売、ネット通販等の全ジャンルで確認する方針です。10,000件は上限ではなく、一般流通品種の収録を優先します。ただし取扱確認できた範囲の拡充であり、「全店・全品種を網羅した」という保証や、新しい追加作業の自動開始を意味しません。

最終件数は**できれば1,000件単位**にするというユーザーの希望を保持します。端数の調整には、取扱と独立した掲載意義を確認できる別の植物・品種を追加します。未確認名・荷姿違いで数を埋めたり、数字を揃えるためだけに適格な掲載対象を落としたりしません。端数が出た結果を、丸い件数の希望が撤回された根拠にはしません。重複・誤同定・対象外の訂正は、数字合わせとは別に行います。

長時間の拡充作業で週間使用枠の**残量0%をライブ確認した場合**は、進行中の変更・検査・記録を安全に区切って停止し、完了範囲と再開点を報告します。使用率0%と残量0%を取り違えず、古い残量記録を現在の停止根拠にしません。この方針は本ツールの作業条件であり、Codex全体の設定やautomationの変更ではありません。

再開時は現行カタログ・作業差分を取得し直します。過去の候補一覧・実行出力・一度限りの整形スクリプトを現行正本や更新許可とみなしません。正規化や照合条件を変更した場合は、カタログの再組立て結果、重複・参照先・流通形への分布継承を検証し、対応する契約・privacy検査と代表例のUI確認をやり直します。新たな公開を行うときは、下記の公開契約を別に満たします。

### 注意事項・未実装・監査待ち

- 原産地域の黒線、気候格子、観測所は別物です。囲まれた地域全体が自生地でも、同じ気候でもありません。海上・非生育地を含む比較点を自動的に代表地点としません。
- 日最高・日最低の暦日平均や月平均は、30年間の極値、寒波・熱波、連続凍結・干ばつ、降霜の頻度を示しません。1991–2020年の気候平均は現在の実況・予報や将来気候でもありません。
- 日射量はエネルギー量で、日照時間・日長・植物に届く光量を直接示しません。相対湿度は葉面の濡れ・霧・露や鉢の乾燥を表しません。年降水量だけで雨季・乾季、水やり、排水を決めません。
- 標高、地形、林内／樹上／岩上、土質・排水、通風、地温、根域、温室・室内・鉢植えといった微環境、休眠・生育期、産地・品種・台木・活着状態を別に確かめる必要があります。
- 実際の自生域・出現点・生息環境ポリゴン、植物別の代表自生地点、標高・霧・風のレイヤー、園芸品種間の耐性比較、多年の変動幅・極端現象、栽培可否判定、3地点以上の保存は未実装です。原種／園芸品種の区別と個別注釈は実装済みですが、体系的な品種関係データベースはありません。
- 公開ファイルの一致や操作確認は、気候推定の科学的精度、全種の星評価の妥当性、原産地域・出典の完全な監査を保証しません。日本の推定値と海外の粗い格子の差、日射の観測所の少なさ、湿度の再現性、資料の種・変種・属の粒度差、星の便宜的な編集基準は独立した監査候補として残ります。
- GBIF等は将来の調査候補です。ERA5-Landは下記の代表地点比較まで実施しましたが、現行の気候データ源には採用していません。導入時には利用条件、統計・分布の妥当性、解像度、費用・性能を確認します。監査候補の記載は追加実装や全データ再処理の許可ではありません。
- 代表地点の限定照合済みと、原因の切り分け・追加検証の未実施を区別します。科学的解釈、学名・分布・星の根拠、適切な比較地点への導線等は、依頼された代表例から調べます。観測事実・推測・未確認・提案を分け、公開ファイルの一致を科学的精度の証明にしません。

### 代表地点の観測照合と保留中の追加検証

## プライバシーとセキュリティ

- Cookie、アクセス解析、現在地取得、フォーム、アカウント機能、永続的な端末保存を使用しない。比較基準はページを開いている間だけメモリに保持
- 詳細地図・航空写真・地形を表示すると、表示範囲のタイル番号と通常の通信情報を国土地理院へ送信する。対象レイヤーを有効にした表示範囲だけを取得する
- NASA POWERへのリクエストは気象格子の中心座標だけを送り、`credentials: omit` と `referrerPolicy: no-referrer` を指定
- 外部JavaScript、外部CSS、広告タグを読み込まない
- Content Security Policyで接続先を同一originとNASA POWERに限定
- API応答をHTMLとして挿入せず、検証した数値だけを`textContent`で表示
- 直前のリクエストを中止し、連続クリックで古い応答が新しい地点を上書きしない
- 公開成果物を固定allowlistから組み立て、SHA-256 manifestと公開後の全ファイル照合を行う
- 公開前CIで現行ファイルと到達可能なGit履歴、author/committer identity、秘密情報らしい文字列を検査
- このローカルcloneは`.githooks/pre-push`を有効化し、GitHubへ送る前にも同じ全ファイル・全履歴検査を実行
- GitHub Secret scanningとPush protectionを有効化
- GitHub ActionsはGitHub公式Actionだけを許可し、完全なcommit SHAで固定。既定権限はreadで、pull request承認権限を与えない

日本以外の地点選択時には、中心座標と通常の通信情報がNASA POWERへ送信されます。日本の地点選択では同一originの配信データだけを読み込みます。この外部送信の区別は画面にも表示します。

## 公開

`privacy-gate.yml`はpushとpull requestで公開ファイルと全履歴を検査します。`pages.yml`は同じ検査に合格した固定allowlistだけをPages成果物にし、公開後にsource commit、全ファイルのbyte数とSHA-256、HTTPS、HSTS、404を検証します。

公開中のsource commit・全配信ファイルのbyte数とSHA-256は、公開 [deployment.json](https://nature-wx-lab.github.io/plant-climate-map/deployment.json) が所有します。[Pages workflow](https://github.com/nature-wx-lab/plant-climate-map/actions/workflows/pages.yml) の `verify-public` は配信された全ファイルの実bytesとtransportを検証します。公開報告では、そのsource commitとローカルの全allowlist・SHA-256が一致することを別に確認します。

カタログを公開するときは、ローカル版と公開版で代表的な検索、ジャンル、100→200件の追加表示、流通品種の囲い非表示、関連種への切替を確認します。PCとスマートフォンで読み込み・検索・横はみ出しも確認し、作業用タブとグループを0に戻します。気候推定の科学的精度や未実装の監査項目は、これらの配信・操作検査と区別します。

新しいcloneでpush前検査を有効にする場合は、repo直下で次を1回実行します。

```bash
git config core.hooksPath .githooks
```

公開用Git identityは次の2種類だけを許可します。

- `nature-wx-lab` / `nature-wx-lab@users.noreply.github.com`
- `github-actions[bot]` / `41898282+github-actions[bot]@users.noreply.github.com`
